HTTP ili HTTPS?

HTTP omogućava komunikaciju između browsera i servera, ali sam po sebi ne obezbeđuje enkripciju podataka. HTTPS koristi TLS zaštitu kako bi komunikacija bila poverljivija, zaštićena od neovlašćenih izmena i povezana sa proverenim identitetom servera.

TLS protokol

Kako se uspostavlja sigurna komunikacija?

Pojednostavljeni prikaz tri ključne faze uspostavljanja HTTPS komunikacije.

01

Uspostavljanje TLS veze

Klijent i server započinju TLS handshake, dogovaraju parametre zaštite i uspostavljaju potrebne kriptografske ključeve.

02

Provera sertifikata

Klijent proverava sertifikat servera, uključujući njegovu vezu sa domenom i poverljivost lanca sertifikata. Time se potvrđuje identitet servera za dati domen.

03

Zaštićena razmena

Nakon uspešnog uspostavljanja zaštite, HTTP sadržaj se prenosi pomoću šifrovane i integritetom zaštićene komunikacije.

Bezbednost na internetu

Šta HTTPS štiti, a šta ne?

HTTPS je važan sloj bezbednosti, ali treba razumeti njegove mogućnosti i ograničenja.

Šta TLS šifruje?

HTTP putanju, parametre upita, zaglavlja i telo poruke tokom prenosa. To štiti, na primer, sadržaj formulara od običnog pasivnog presretanja.

Šta i dalje može biti vidljivo?

Mrežni posmatrač i dalje može da vidi određene metapodatke, kao što su IP adrese i obrasci saobraćaja. Domen može biti otkriven kroz DNS ili TLS rukovanje, zavisno od konfiguracije.

Da li HTTPS garantuje bezbedan sajt?

Ne. I zlonameran ili lažan web sajt može koristiti validan HTTPS sertifikat. HTTPS štiti komunikaciju, ali ne potvrđuje da je sadržaj sajta bezopasan.

Zašto je HTTPS važan?

Štiti podatke u prenosu, smanjuje rizik od prisluškivanja i neovlašćenog menjanja sadržaja i omogućava sigurniju osnovu za web aplikacije.

Zapamti

HTTPS je HTTP sa zaštitom prenosa.

HTTP definiše način razmene zahteva i odgovora. HTTPS koristi TLS zaštitu kako bi sadržaj te komunikacije bio šifrovan tokom prenosa, a identitet servera proveren. Zbog toga je HTTPS standardan izbor za savremene javne web sajtove.
